# Avance - 19 de Mayo 2026

## Objetivo

Integrar el microservicio de Logística (`https://modulo-logistica.fly.dev`) al módulo de Negocios, permitiendo que los pedidos puedan ser despachados a Logística para su entrega y que Logística pueda notificar cambios de estado vía callback.

---

## Cambios Realizados

### 1. Instalación de dependencias

Se agregó `@nestjs/axios` + `axios` para hacer peticiones HTTP al microservicio de Logística.

```bash
npm install @nestjs/axios axios
```

#### LogisticsClientService

Métodos expuestos:

- `createDelivery(dto)` → `POST /api/logistica/entregas` — Crear entrega en Logística
- `getDelivery(id)` → `GET /api/logistica/entregas/:id` — Consultar entrega
- `getDeliveryHistory(id)` → `GET /api/logistica/entregas/:id/historial` — Historial de estados
- `listDeliveries(moduloOrigen, page, limit)` → `GET /api/logistica/entregas?modulo_origen=...` — Listar entregas
- `checkHealth()` → `GET /health` — Health check de Logística

#### LogisticsCallbackController

Endpoint que Logística usa para notificar cambios de estado:

```
PATCH /api/negocios/:businessId/pedidos/:businessOrderId/estado-logistica
```

Recibe un payload con `negocioId`, `pedidoId`, `estado`, `codigo_entrega`, etc., mapea el estado al enum local y actualiza el registro de delivery vía `DeliveriesService.updateStatus()`.

#### Nuevo endpoint de despacho

```
POST /api/businesses/:businessId/orders/:businessOrderId/dispatch
```

Flujo:
1. Valida que el pedido esté en estado `confirmed`, `preparing` o `ready_for_pickup`
2. Verifica que no tenga un delivery ya vinculado
3. Construye el payload y llama a Logística (`POST /api/logistica/entregas`)
4. Vincula la entrega localmente (`business_order_delivery`)
5. Retorna el detalle de la entrega (tanto en Logística como local)

#### DTO de respuesta
