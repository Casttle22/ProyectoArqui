## 1. Corrección de errores de compilación (deploy)

### Error 1: Tipo en `allowedStatuses.includes()`

**Archivo:** `src/modules/orders/application/services/orders.service.ts:387`

```typescript
// Antes (infería tipo estrecho)
const allowedStatuses = [
  business_order_order_status.confirmed,
  business_order_order_status.preparing,
  business_order_order_status.ready_for_pickup,
];

// Después (tipo explícito)
const allowedStatuses: business_order_order_status[] = [
  business_order_order_status.confirmed,
  business_order_order_status.preparing,
  business_order_order_status.ready_for_pickup,
];
```

TypeScript infería el arreglo como `("confirmed" | "preparing" | "ready_for_pickup")[]` y `.includes()` no aceptaba `business_order_order_status` (que incluye otros valores como `"delivered"`).

### Error 2: Propiedad `business_order_delivery` no existía en el tipo

**Archivo:** `src/modules/orders/infrastructure/repositories/prisma-orders.repository.ts:34-44`

```typescript
// Antes: faltaba business_order_delivery
const logisticsOrderWithRelations = Prisma.validator<Prisma.business_orderDefaultArgs>()({
  include: { business: true, business_order_detail: { orderBy: { business_order_detail_id: 'asc' } } },
});

// Después: se agregó la relación
const logisticsOrderWithRelations = Prisma.validator<Prisma.business_orderDefaultArgs>()({
  include: {
    business: true,
    business_order_detail: { orderBy: { business_order_detail_id: 'asc' } },
    business_order_delivery: true,
  },
});
```

### Error 3: Dependencia `DeliveriesService` no resoluble

**Archivo:** `src/modules/orders/orders.module.ts`

Se importó `DeliveriesModule` en `OrdersModule` porque `OrdersService` requiere `DeliveriesService`.

### Nuevo endpoint de pago

```
POST /api/businesses/:businessId/orders/:businessOrderId/payment
```

**Archivo:** `src/modules/orders/presentation/controllers/business-orders.controller.ts` (nuevo método `processPayment`)

**Flujo:**
1. Valida que el pedido no esté cancelado
2. Valida que no tenga un cobro ya procesado (`external_payment_code`)
3. Construye payload con items y montos del pedido
4. Llama `POST /api/cobros/payments` a Cobros
5. Guarda `cobro_id` (payment_id) en `external_payment_code` del pedido vía `ordersRepository.updatePaymentCode()`
6. Retorna `{ success, cobro_id, status, settlement_status }`

## 4. Flujo final de pedidos

```
POST /api/businesses/:businessId/orders
  → Crea pedido con reserva de inventario (estado: reserved)

POST /api/internal/business-orders/confirm-order
  → Confirma pedido (consume reserva, estado: confirmed)

PATCH /api/businesses/:businessId/orders/:id/preparing
  → Cocina prepara (estado: preparing)

PATCH /api/businesses/:businessId/orders/:id/ready-for-pickup
  → Listo para recoger (estado: ready_for_pickup)

POST /api/businesses/:businessId/orders/:id/payment          ← NUEVO
  → Cobra en Cobros, guarda cobro_id (obligatorio antes de despachar)

POST /api/businesses/:businessId/orders/:id/dispatch
  → Exige cobro_id, envía a Logística, vincula delivery
```
